09/12/26 -Went down a rabbit hole of trying to clean up my lexical_analyzer function, as it was large and convoluted, despite working.  Unfortunately my efforts did clean up the function by breaking the logic down into string tokenizer functionality and type categorizing functionality, it had the side effect of creating a new memory bug and causing the project to no longer be "valgrind clean". As of today, we are clear of memory bugs again. Although valgrind reported an issue in my free_token function, the issue was actually with how I implemented my array of tokens in token_stream. Originally the stream was implemented as Tokens* (one asterisk).
 This will compile and will generally run properly, however this creates an Array of actual Tokens. Not only is this not the behavior we want but when realloc is called in push_token, any reference to them will potentially be broken.  If the program is small, realloc will generally just find more room after the initial array, and the program will continue. However, the memory is technically no longer accessible and could potentially
hold garbage data.  This becomes an issue when attempting to free the individual tokens, or if realloc can not find space adjacent to the initial arrays all Tokens will be recopied somewhere else in memory Token** (two asterisks) solves this, as TokenStream is meant to simply be an array of pointers to tokens.  As of today, we have a functional lexer that creates a stream of usable tokens, and is clear of any memory bugs.  We're ready to start the Parser.
